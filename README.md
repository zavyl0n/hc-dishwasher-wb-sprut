# Посудомойка Bosch / Siemens (Home Connect) → Wiren Board 7 → Sprut.hub, без облака

Локальное управление посудомоечной машиной с Home Connect: статус, выбор программы, опции,
старт, отложенный старт, отмена, настройки машины, аварии и уведомления. Всё работает внутри
вашей сети, облако Bosch и интернет для работы не нужны.

```
Посудомойка ⇄ Wi-Fi ⇄ hcpy (на WB7) ⇄ MQTT ⇄ правило wb-rules ⇄ Sprut.hub (→ HomeKit / Алиса)
```

- **[hcpy](https://github.com/hcpy2-0/hcpy)** подключается к машине напрямую по локальной сети с её ключом и публикует всё в MQTT.
- **Правило `dishwasher.js`** создаёт в Wiren Board устройство «Посудомоечная машина» и переводит нажатия в команды машине.
- **Шаблон Sprut.hub** показывает это устройство в Sprut.hub.
- **Генератор `tools/make_kit.py`** собирает правило и шаблон под вашу модель по её `devices.json`.

Проверено на Bosch SMV4HVX31E + Wiren Board 7 + Sprut.hub 1.12. Другие модели поддерживаются
через генератор, но на живых машинах не проверялись — пишите, что получилось.

## Что нужно

- **Wiren Board 7** с доступом по SSH, **wb-rules 2.42+** и пакетом **mosquitto-clients**. На время установки hcpy нужен интернет на WB.
- **Посудомойка Bosch / Siemens / Neff с Home Connect и локальным TLS-PSK (порт 443)**, один раз подключённая к Wi-Fi через приложение Home Connect. Профили с полем `iv` используют AES на порту 80 и этим комплектом WB7 не поддерживаются.
- **`devices.json`** — ключи доступа к вашей машине, получаются один раз через аккаунт Home Connect.
- **Python 3.8+** на компьютере или на WB — для генератора.
- **Sprut.hub 1.12.2+** с MQTT-контроллером, подключённым к брокеру WB (если нужен Sprut.hub).

## Состав

```
hcpy_wb7/            установщик hcpy для WB7 (hcpy + патч, см. app/VERSION; всё ставится в /mnt/data/hcpy)
rule/dishwasher.js   правило wb-rules (исходник, блок «МОДЕЛЬ» заполняет генератор)
tools/make_kit.py    генератор: devices.json → out/dishwasher.js + out/spruthub_dishwasher.json
tools/hc_check.py    проверка ключа: отвечает ли машина по локальной сети (нужен Python 3.13+)
examples/SMV4HVX31E/ готовый результат генератора для Bosch SMV4HVX31E (и компактный вариант шаблона)
tests/               тесты (для разработки, на WB не нужны)
```

## Установка

### 1. Получите devices.json

`devices.json` содержит ключи доступа к машине. Его нужно получить один раз через аккаунт
Home Connect — по инструкции hcpy (раздел
[Authenticate to the cloud servers](https://github.com/hcpy2-0/hcpy#authenticate-to-the-cloud-servers))
или утилитой [homeconnect-profile-downloader](https://github.com/bruestel/homeconnect-profile-downloader).

Затем откройте файл в текстовом редакторе и проверьте у посудомойки два поля:

- **`host`** — IP-адрес машины, например `"192.168.1.50"`. Закрепите этот адрес за машиной
  в роутере (резервирование DHCP), иначе после смены IP связь пропадёт.
- **`name`** — латиницей, например `"dishwasher"`. Из него получаются MQTT-топики `homeconnect/<name>/...`.

> ⚠ **`devices.json` — секрет.** С ним можно управлять вашей машиной. Не выкладывайте его
> и не присылайте в чаты. В этом репозитории он внесён в `.gitignore`.

По желанию проверьте ключ с компьютера (Python 3.13+), машина должна быть включена.
Если в `devices.json` несколько приборов, скрипт возьмёт тот, у которого `host` совпадает с указанным IP:

```bash
python tools/hc_check.py 192.168.1.50 devices.json
```

### 2. Установите hcpy на WB7

На WB по SSH от root создайте закрытый каталог для установщика и ключа:

```bash
umask 077
mktemp -d /root/hcpy-install.XXXXXXXX
```

Подставьте выведенный каталог вместо `/root/hcpy-install.XXXXXXXX` в следующих командах. С компьютера скопируйте туда папку `hcpy_wb7` и файл `devices.json` через `scp` или WinSCP:

```bash
scp -r hcpy_wb7 devices.json root@<IP-WB>:/root/hcpy-install.XXXXXXXX/
```

Включите посудомойку. На WB по SSH:

```bash
stage=/root/hcpy-install.XXXXXXXX
bash "$stage/hcpy_wb7/install_hcpy.sh" --devices "$stage/devices.json"
```

Если в файле несколько приборов, добавьте `--device dishwasher`, подставив имя посудомойки из профиля.

Установщик кладёт всё в `/mnt/data/hcpy`, скачивает [uv](https://github.com/astral-sh/uv)
(с проверкой SHA-256) и Python 3.13, проверяет `devices.json` (и убирает BOM, если файл сохранял
Блокнот Windows), ставит зависимости по хешам и ждёт актуальный признак готовности от выбранной машины.
Версии и хеши закреплены и у пакетов (`requirements-wb7.txt`), и у того, чем на контроллере собирается
`paho-mqtt`, который выходит только в исходниках (`build-constraints-wb7.txt`).
Сохранённое брокером значение исключается из проверки. Если машина не передала данные, установщик завершится с ошибкой.
После успешной проверки включите автозапуск:

```bash
bash /mnt/data/hcpy/install_hcpy.sh --service
```

Служба работает от отдельного пользователя `hcpy` с ограничениями systemd. Если брокер MQTT требует пароль,
используйте команду из раздела «Безопасность». Исходный файл профиля остаётся в закрытом каталоге.
Когда служба заработает, удалите эту копию ключа с WB.

Удалить всё: `bash /mnt/data/hcpy/install_hcpy.sh --remove`.

### 3. Соберите правило и шаблон под свою модель

На компьютере в папке набора:

```bash
python tools/make_kit.py путь/к/devices.json
```

или прямо на WB из закрытого каталога, в который скопирован весь репозиторий:

```bash
python3 "$stage/tools/make_kit.py" /mnt/data/hcpy/config/devices.json --out "$stage/out"
```

Генератор покажет найденные программы, опции и настройки и предупредит, если чего-то нет
(например, отложенного старта или датчика двери). Строка «Машина не сообщает» — состояния и события,
которые правило умеет показывать, но этой модели нет; «События, которых правило не знает» — пришлите их,
добавим. Результат — в папке `out/`:

- `dishwasher.js` — правило для Wiren Board;
- `spruthub_dishwasher.json` — шаблон для Sprut.hub.

Из `devices.json` генератор берёт только описание возможностей машины; ключи он не читает и никуда не пишет.

Вид в Sprut.hub можно подстроить. Эти параметры меняют только шаблон, правило остаётся тем же,
поэтому шаблон можно пересобрать и заменить отдельно:

| Параметр | Что меняет |
|---|---|
| `--sprut-programs Eco50,Quick65` | Плитки остаются только у перечисленных программ, в указанном порядке. Остальные программы остаются скрытыми сервисами, как настройки машины. Ключи программ генератор печатает в квадратных скобках |
| `--sprut-compact` | Близкие параметры собраны в общие сервисы: «Состояние» вместе с прогрессом и связью, «Осталось» вместе с минутами, «Старт через» вместе с разрешением удалённого старта, «Отложить на» вместе с «Завершить к». На 4 плитки меньше |
| `--sprut-settings-options` | Настройки машины становятся опциями устройства (⚙) со списками значений: «Жёсткость воды: 0 (без соли)…7» вместо числа в скрытом сервисе |

`--sprut-compact` и `--sprut-settings-options` на живом Sprut.hub пока не проверены, поэтому выключены
по умолчанию. После `--sprut-settings-options` добавьте устройство и сверьте настройки машины
с Wiren Board: не проверено, что Sprut.hub не запишет в машину начальные значения из шаблона
(первое значение каждого списка).

### 4. Загрузите правило в Wiren Board

Веб-интерфейс WB → **Правила** → создать правило `dishwasher.js` → вставить содержимое
`out/dishwasher.js` → **Сохранить**. Или скопируйте файл в `/etc/wb-rules/`.

В разделе **Устройства** появится «Посудомоечная машина». Параметр «Связь с машиной» должен быть включён.

Чтобы машина принимала команду старта, на ней должен быть разрешён удалённый старт
(кнопка Remote Start или настройка «Постоянный удалённый старт»).

Настройки в начале правила (блок `CFG`):

| Параметр | Что делает |
|---|---|
| `tgToken`, `tgChatId` | Уведомления в Telegram (старт, окончание, аварии, соль, ополаскиватель). Пусто — только лог и «Последнее событие» |
| `unloadReminderMin` | Напомнить «посуда не выгружена» через N минут после окончания (0 — выкл) |
| `notifyStart` | Уведомлять о старте и отложенном старте |
| `delayStepSec` | Шаг отложенного старта. Если машина не принимает отложенный старт, поставьте 3600. Действует, когда в блоке «МОДЕЛЬ» `DELAY_STEP = 0` (генератор не нашёл шаг в `devices.json`) |
| `powerOnDelayMs` | Время ожидания подтверждения питания от машины перед запуском. По умолчанию 5000 мс |
| `resetDelayOnStart` | Сбрасывать «Отложить старт» и «Завершить к» после старта программы (по умолчанию да). `false` — значения сохраняются для следующих запусков |

### 5. Добавьте шаблон в Sprut.hub (1.12.2+)

1. **Каталог** → **+** справа вверху → контроллер **MQTT** → **Создать** → вставьте
   `out/spruthub_dishwasher.json` → **Сохранить**. Если редактор подсветил что-то жёлтым,
   кнопка сохранения недоступна — пришлите, что подсвечено.
2. **Контроллеры** → MQTT → **⋯** → **Поиск устройств**. Появится «Посудомоечная машина».

Рекомендуемая настройка в Sprut.hub (⚙ в карточке устройства):

- **Комната** — перенесите в кухню.
- **Видимость → Рабочий стол** — по умолчанию каждый сервис выводится отдельной плиткой,
  оставьте одну-две. Настройки машины скрыты шаблоном. Уменьшить число плиток заранее помогают
  параметры генератора `--sprut-programs` и `--sprut-compact` (шаг 3).
- **Диагностика** — прошивка, обновление ПО, Wi-Fi, всего запусков, прогнозы расхода — не сервисы,
  а параметры устройства только для чтения: ⚙ в карточке устройства.
- **Видимость → Экран управления** — включите «Соль», «Ополаскиватель», «Уход за машиной»
  и «Фильтр», если они есть в профиле машины. Шаблон добавляет эти сервисы только при наличии
  соответствующих возможностей в профиле. Sprut.hub по умолчанию скрывает характеристики фильтров.
- ⚠ **Плитка «Мойка» по нажатию запускает или отменяет мойку.** Если это опасно (дети, гости),
  уберите её с рабочего стола и выведите вместо неё «Состояние», переименовав его
  (⚙ → Переименование) например в «Посудомоечная машина». Нажатие на такую плитку просто открывает
  карточку со всем управлением. Учтите: на плитке параметра Sprut.hub показывает только название, без значения.

## Что получится

| | Wiren Board | Sprut.hub |
|---|---|---|
| Статус | состояние, фаза, прогресс, осталось, окончание, старт через, дверь, связь | то же + кран «Мойка» с обратным отсчётом |
| Управление | питание, программа, опции, «Старт», «Отменить», отложить на N ч, «Завершить к ЧЧ:ММ» | питание, выключатели программ и опций, «Мойка» (старт/отмена), отложенный старт |
| Обслуживание | соль, ополаскиватель, уход за машиной, фильтр, циклов до ухода | то же, как «Обслуживание фильтра» |
| Аварии | AquaStop, давление воды, слив, ошибки, коды ошибок | датчик протечки AquaStop, «Неисправность» у крана, текст аварий |
| Настройки машины | все поддерживаемые моделью: жёсткость, ополаскиватель, громкость, InfoLight… | скрытые сервисы в карточке или опции устройства со списками значений (`--sprut-settings-options`) |
| Диагностика | прошивка, Wi-Fi, всего запусков, прогнозы расхода энергии и воды | параметры устройства только для чтения (⚙) |
| Уведомления | старт, окончание, «не выгружена», аварии, соль/ополаскиватель (лог, Telegram) | датчик «Мойка завершена» для своих сценариев |

Если машина не приняла команду, переключатель через 15 с вернётся в реальное положение.
Для запуска нужны актуальная связь с машиной, разрешение на удалённый старт, подтверждённое питание
и закрытая дверь, если модель сообщает о ней. Пока правило ждёт включения питания, запрос
можно снять кнопкой «Отменить» или выключателем «Мойка». Во время мойки и отмены питание
заблокировано. Если к времени «Завершить к» программа уже не успевает, она запустится сразу,
а в «Последнем событии» будет видно, когда она закончится. Отложить дольше, чем позволяет машина,
нельзя: ползунок ограничен её максимумом.

Если связь с машиной прерывалась (перезапуск hcpy, Wi-Fi), правило сравнивает первое состояние после
восстановления с последним до разрыва: уведомление о мойке, которая за это время началась или
закончилась, придёт, когда связь вернётся. Не сработает это в двух случаях: wb-rules перезапускался,
пока связи не было, или машина после окончания уже выключилась.

## Обновление

1. **Правило.** Пересоберите его новой версией набора, перенеся свои настройки `CFG`
   (токен Telegram и т. п.) из установленного правила. На WB:

   ```bash
   python3 "$stage/tools/make_kit.py" /mnt/data/hcpy/config/devices.json --out "$stage/out" \
       --keep-cfg /etc/wb-rules/dishwasher.js
   ```

   Генератор напишет, какие параметры перенёс (значения не печатает) и какие появились.
   На компьютере сохраните текущий текст правила из веб-интерфейса WB в файл и укажите его в `--keep-cfg`.
   Затем замените правило (шаг 4).
2. **hcpy.** Запустите `install_hcpy.sh` из новой версии набора без `--devices`, чтобы использовать
   сохранённый профиль. Установщик готовит приложение и зависимости отдельно. Если служба уже
   работает, установщик переключит её на новую версию после проверки импорта, перезапустит и до 30 с
   ждёт, пока новая служба передаст актуальный признак готовности машины — как при установке.
   Поэтому обновляйте, когда посудомойка в сети. Если перезапуск завершится ошибкой или данные
   от машины не придут (например, из-за неверного пароля MQTT), установщик покажет журнал службы
   и вернёт прежнюю версию и конфигурацию.
3. **Шаблон Sprut.hub** нужно менять, только если новый `out/spruthub_dishwasher.json` отличается от старого.
   Прежний шаблон привязан к тем же контролам правила, поэтому замена не срочная. Если в новом
   шаблоне изменился состав сервисов (например, диагностика переехала в параметры устройства
   или включён `--sprut-compact`), после замены проверьте сценарии и настройки видимости,
   привязанные к прежним сервисам.

## Работа без облака

- Для повседневной работы облако не нужно: hcpy общается с машиной напрямую.
- **Рекомендуем закрыть машине доступ в интернет** в роутере — тогда облако не сможет
  обновить прошивку и случайно сломать локальный протокол.
- Без интернета вы теряете приложение Home Connect, обновления и синхронизацию часов машины
  (отложенный старт от часов машины не зависит).
- Облако понадобится, если сменить Wi-Fi (имя или пароль сети), сбросить машину или заново
  привязать её в приложении. После сброса ключи меняются — нужен новый `devices.json`.

## Безопасность

- **Брокер MQTT — пульт от машины.** Кто может публиковать в `homeconnect/dishwasher/...`, тот может
  запустить мойку, поменять настройки машины или подделать для правила «AquaStop». Если брокер WB
  принимает подключения без пароля со всей сети, это может любое устройство в ней.
- Держите WB и посудомойку в доверенной сети, гостевой Wi-Fi отделите от неё.
- Включите на брокере WB вход по паролю — по инструкции Wiren Board для вашей версии прошивки,
  так, чтобы собственные службы WB продолжили работать. Потом проверьте веб-интерфейс WB и Sprut.hub
  (в Sprut.hub логин и пароль задаются в настройках MQTT-контроллера).
- Передайте пароль hcpy через приглашение в SSH. Затем выполните `--service`. Пароль хранится в
  `/mnt/data/hcpy/config/hcpy.ini` с правами 600.

  ```bash
  read -rsp 'Пароль MQTT: ' MQTT_PASS
  printf '\n'
  MQTT_USER=логин MQTT_PASS="$MQTT_PASS" bash "$stage/hcpy_wb7/install_hcpy.sh" --devices "$stage/devices.json"
  unset MQTT_PASS
  ```

  Чтобы убрать пароль, удалите этот файл и снова выполните `--service`.
- `devices.json` лежит в `/mnt/data/hcpy/config` с правами 600 и тоже доступен только службе.
- Если служба hcpy из-за ограничений systemd не запускается на вашей прошивке, вернуть прежний запуск
  от root без ограничений: `HARDEN=0 bash /mnt/data/hcpy/install_hcpy.sh --service` (выбор запоминается
  и для обновлений; `HARDEN=1` вернёт ограничения). Напишите об этом.

## Ограничения

- Отмену программы некоторые машины не принимают (команда `AbortProgram` у них без доступа на запись).
- Опции, выбранные до старта, применяются к выбранной программе; если программа их не поддерживает,
  переключатель вернётся через 15 с.
- В Apple «Дом» обратный отсчёт длиннее часа может отображаться с ограничением.
- Одна посудомойка на один WB (устройство WB всегда называется `dishwasher`).
- hcpy — неофициальный проект, протокол разобран энтузиастами. Новая прошивка машины может его сломать.

## Диагностика

На WB:

```bash
systemctl status hcpy --no-pager | head -5        # служба hcpy работает?
journalctl -u hcpy -n 30 --no-pager               # ошибки подключения к машине
mosquitto_sub -t 'homeconnect/#' -v -W 5          # что публикует hcpy
journalctl -u wb-rules -f | grep dishwasher       # что делает правило
```

Быстрый живой тест: включите и выключите «Питание» в WB или Sprut.hub. Если переключатель
остаётся в нужном положении дольше 15 секунд — связь с машиной в обе стороны работает.

## Тесты

Для разработки: проверяют правило, генератор и `hc_check.py` без машины, WB и Sprut.hub.
Нужны Node.js 18+ и Python 3.9+ (сквозной тест `hc_check.py` и тест установщика — 3.13+, bash).

```bash
npm install                                               # acorn для проверки синтаксиса ES5
pip install --require-hashes -r hcpy_wb7/requirements-wb7.txt   # по желанию: тесты публикации hc2mqtt
npm test
```

- `tests/rule.test.js` — правило в эмуляторе wb-rules (`tests/wbrules.js`): поддельное время,
  только функции ES5 (как в Duktape), проверка типов контролов. Сценарии: отображение состояния,
  команды, отказы, возврат контрола через 15 с, отложенный старт, уведомления, связь с hcpy.
- `tests/test_hcpy_contract.py` — стык с hcpy: каждую команду правила проверяют валидаторы hcpy,
  а формат значений hcpy — правило. Здесь же проверки поставки: зависимости закреплены по хешам,
  мост запускается без PyYAML, а `wb7-changes.patch` — полное отличие `hcpy_wb7/app` от исходного hcpy
  (откат патча даёт файлы с хешами из `UPSTREAM.sha256`).
- `tests/test_make_kit.py` — генератор: точное совпадение с `examples/`, модели без отложенного
  старта и отмены, неизвестные программы и опции, отсутствие ключей в результате, структура шаблона
  во всех вариантах вида Sprut.hub (каждый вариант привязывает те же контролы правила).
- `tests/test_hc_check.py` — выбор прибора, разбор WebSocket и TLS-PSK с поддельной машиной.
- `tests/test_install.py` — установщик с заглушками вместо systemd, uv и т. п.: перенос и проверка
  `devices.json`, файл с паролем MQTT, юнит службы, обновление (с проверкой связи и откатом) и удаление.
- `tests/duktape/` — короткий сценарий на чистом ES5. В CI он идёт в настоящем Duktape — движке wb-rules,
  локально `tests/duktape.test.js` гоняет его в Node.

Фикстуры в `tests/fixtures` синтетические, ключи в них ненастоящие. После правки `rule/dishwasher.js`
перегенерируйте пример: `python3 tools/make_kit.py tests/fixtures/smv4hvx31e.json --out examples/SMV4HVX31E`.
После правки шаблона обновите и `examples/SMV4HVX31E/spruthub_dishwasher_compact.json`: это
`spruthub_dishwasher.json` из той же команды с `--sprut-compact` и другой папкой `--out`.
После правки файлов в `hcpy_wb7/app` обновите `wb7-changes.patch` (diff с версией из `VERSION`) и описание в `VERSION`.
